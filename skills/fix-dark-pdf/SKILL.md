# Fix Dark-Theme PDF

## Overview

Typora (Chromium/Electron) exports PDFs with CID Type 0C (CFF OpenType) fonts + Identity-H encoding. Some PDF viewers cannot render these fonts, showing garbled text. The outline/bookmarks display correctly because they are stored as Unicode strings independent of font rendering. This skill fixes both font compatibility and dark-theme colors in one pipeline.

## When to Use

- PDF shows garbled text (乱码) but bookmarks/outline are correct
- PDF has dark background unsuitable for printing
- PDF was generated by Typora, Chrome print-to-PDF, or other Chromium-based tools
- `pdffonts` shows "CID Type 0C" with "Identity-H" encoding

## Diagnosis

```bash
pdffonts input.pdf    # Look for "CID Type 0C" + "Identity-H"
pdfinfo input.pdf     # Check Creator: "Typora" or "Chromium"
pdftotext input.pdf - | head -20  # Text extraction works = fonts are embedded but viewer can't render
```

## Pipeline

Run the bundled script:

```bash
python3 ~/.claude/skills/fix-dark-pdf/fix_dark_pdf.py input.pdf output.pdf
```

The script performs these steps in order:

1. **Scan colors** — collect all RGB colors from all page content streams and XObject Forms (header/footer bars)
2. **Classify by brightness** — dark colors (background), light colors (text), mid-range (accents/borders)
3. **Replace colors** — dark backgrounds → white, light text → dark, accents → adjusted for white background contrast
4. **Reprocess fonts** — `pdftocairo -pdf` re-embeds fonts for better viewer compatibility
5. **Copy bookmarks** — extract outline tree from original, remap page references, write to output

## Dependencies

- Python 3 with `pikepdf` (`pip3 install pikepdf`)
- `pdftocairo` from poppler-utils (`apt install poppler-utils` or `brew install poppler`)

## Key Technical Details

- **XObject Forms**: Header/footer are embedded as `/Subtype /Form` XObjects with independent content streams — must be processed alongside page content streams
- **Color replacement**: Uses regex on decompressed content streams, matching both `rg` (fill) and `RG` (stroke) operators
- **Bookmark remapping**: Uses pikepdf's OutlineItem API; destinations are remapped to corresponding pages in the new PDF using `/Fit` view
- **Font format unchanged**: pdftocairo re-renders through Cairo but may keep CID Type 0C; the reprocessing still improves compatibility with most viewers

## Common Mistakes

- Only modifying page content streams and missing XObject Forms → header/footer bars stay dark
- Using Ghostscript (`gs`) instead of pdftocairo → often loses ToUnicode mappings, breaking text extraction
- Not preserving bookmarks after pdftocairo → outline/TOC disappears
