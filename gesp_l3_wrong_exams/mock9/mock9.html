一、单选题（每题 2 分，共 30 分）
1. 函数 hmean(a, b) 在 a==-b 时会 `throw runtime_error("Runtime error occurred.")`，main 中 `x=10, y=-10` 调用 `hmean(x,y)`，并有 `catch (const runtime_error& e) {...}` 和 `catch (...) {...}`，运行结果是（ ）。
A. 屏幕上输出 "Caught: Runtime error occurred."
B. 屏幕上输出 "Caught an unknown exception."
C. 程序调用 std::terminate() 崩溃
D. 编译错误
2. 如果程序中有一个 `try` 块，但抛出的异常类型没有对应的 `catch` 能匹配，会发生什么（ ）。
A. 程序会自动修复并继续运行
B. 程序调用 std::terminate()，直接终止（崩溃）
C. 忽略这个异常，继续往下执行
D. 自动跳到 main 函数重新开始
3. 关于自定义异常类，下列写法正确的是（ ）。
A. 异常类必须继承自 int 类型
B. throw 语句只能抛出 int 或 string，不能抛出自定义类对象
C. class MyError { public: string reason; int code; MyError(string r, int c): reason(r), code(c) {} }; 定义好后可以 `throw MyError("超重", 5);`
D. catch 块无法通过引用接收自定义异常类对象
4. 关于"栈展开"（stack unwinding）和 RAII，说法正确的是（ ）。
A. 异常抛出后，调用栈上的局部对象的析构函数不会被调用
B. 异常从被抛出到被 catch 的过程中，途经的函数栈帧上的局部对象会依次被析构（自动释放内存/关闭文件等），这就是栈展开
C. RAII 指的是必须手动在每个 catch 块里释放资源
D. 栈展开只在程序正常返回时发生，异常时不会发生
5. 下面哪种方式**不能**实现把字符串 "Welcome to 2026!" 输出重定向到文件 log.txt（ ）。
A. 用 freopen("log.txt", "w", stdout) 后再用 printf/cout
B. std::ofstream out("log.txt"); out << "Welcome to 2026!";
C. std::ofstream out("log.txt"); cout << "Welcome to 2026!";（没有把 cout 的缓冲区重定向，直接输出到屏幕）
D. cout.rdbuf() 重定向到 ofstream 关联的 streambuf 后，再用 cout <<
6. 下面代码用 ifstream 打开 data.txt 并用 getline 逐行读取输出，对程序功能最准确的描述是（ ）。
ifstream fin("data.txt");
string line;
while (getline(fin, line)) {
    cout << line << endl;
}
A. 从标准输入（键盘）读取每行并输出到屏幕
B. 程序无法运行，因为 getline 只能读取 cin
C. 把 data.txt 文件的每一行内容依次读取并输出到屏幕
D. 程序会创建 data.txt 并写入默认文本
7. 代码把 "Happy" 和 "New Year" 写入 test.txt（中间用空格分隔），再用 `>>` 读取到 s1，再用 `getline` 读取剩余部分到 s2，输出 `s1 << "|" << s2`，结果是（ ）。
ofstream fout("test.txt");
fout << "Happy New Year";
fout.close();
ifstream fin("test.txt");
string s1, s2;
fin >> s1;
getline(fin, s2);
cout << s1 << "|" << s2;
A. Happy|New Year
B. Happy| New Year
C. HappyNew Year|
D. Happy| New Year（getline 会读到 ">>" 留下的那个空格）
8. 关于文件流的状态位，下列描述正确的顺序（检查优先级从高到低）是（ ）。
A. 先查 eof，再查 fail，最后查 bad
B. 只需要查 good 即可，不需要查其他三个
C. 应该先查 bad（硬件级错误最严重），再查 fail（格式错误），最后查 eof（正常读到文件尾）
D. 四个状态位互相排斥，同一时刻只可能有一个为真
9. 文件流对象调用 `clear()` 方法的作用是（ ）。
A. 清空文件内容
B. 清除流对象的错误状态位（如 fail、eof），使流恢复可用
C. 关闭文件
D. 删除文件
10. `文件流.seekg(0, ios::end);` 之后再调用 `文件流.tellg();`，得到的是（ ）。
A. 文件的总字节数（读指针跳到末尾后的位置）
B. 文件的第一个字节内容
C. 永远是 0
D. 文件名的长度
11. 结构体 `struct Rec { string name; int score; };`（含 string 成员），如果直接用 `文件.write((char*)&rec, sizeof(rec));` 把整个结构体写入二进制文件，会有什么问题（ ）。
A. 完全没问题，读写都正常
B. 只有 score 字段能正确保存
C. 编译错误
D. string 内部一般是指向堆内存的指针，直接按字节写入只会保存这个指针本身，重新读取后指针失效，数据损坏或崩溃
12. 要把一个 string 安全地序列化保存进二进制文件，正确的做法是（ ）。
A. 直接 write(&str, sizeof(str))
B. 先写入字符串长度（如一个 int），再写入 str.c_str() 对应的字节内容；读取时先读长度，再 resize 后读入字符内容
C. string 不能被保存到文件中
D. 只需要 write(str.c_str(), 1) 就够了
13. `#include "myheader.h"` 和 `#include <myheader.h>` 的主要区别是（ ）。
A. 双引号形式通常先在当前源文件所在目录查找，再到系统标准路径查找；尖括号形式一般直接按系统标准路径查找
B. 两者完全没有区别，只是写法习惯不同
C. 尖括号只能用于 C 语言，双引号只能用于 C++
D. 双引号形式性能更快
14. 代码 `ofstream out("data.txt"); out << "Hello"; out.close();` 运行后（ ）。
A. 因为 data.txt 一开始不存在，程序会报错
B. "Hello" 会输出到屏幕，不会写入文件
C. 如果 data.txt 不存在会自动创建，并把 "Hello" 写入其中
D. 必须先用 ifstream 打开文件才能用 ofstream 写入
15. 关于文件打开模式，`ofstream out("a.txt", ios::app);` 和默认不加任何模式相比，区别是（ ）。
A. 两者完全一样
B. app（追加）模式会保留文件原有内容，新写入的内容加在末尾；默认模式会先清空原有内容再写入
C. app 模式只能读不能写
D. 默认模式是二进制模式，app 是文本模式

编程题 1：自定义异常——安全除法计算器

时间限制：1.0 s   内存限制：128.0 MB

【问题描述】

设计一个自定义异常类 DivideError（至少包含被除数、除数两个信息），编写一个除法函数：当除数为 0 时抛出该异常；main 函数中用 try-catch 捕获，若捕获到异常，输出 "Error: divide by zero, a=X"（X 为被除数）；若没有异常，输出正常的除法结果（整数除法，向下取整，即 C++ 默认截断行为）。

【输入描述】

一行两个整数 a 和 b。

【输出描述】

若 b 不为 0，输出 a/b（整数除法结果）；若 b 为 0，输出 "Error: divide by zero, a=" 后面接 a 的值（无空格）。

样例输入 1

10 2

样例输出 1

5

样例输入 2

7 0

样例输出 2

Error: divide by zero, a=7

配套测试程序：mock9_prob1_divide_exception.cpp

编程题 2：二进制文件存取学生记录

时间限制：1.0 s   内存限制：128.0 MB

【问题描述】

输入 n 名学生的姓名（不含空格，长度不超过20）和分数，请把这些记录以二进制方式写入一个临时文件（文件名固定为 `students.bin`，写入前如果姓名带 string 需要注意序列化，不能直接对含 string 成员的结构体整体 write），然后立刻从该文件重新读取出来，按"姓名 分数"的格式输出（用于验证你的二进制序列化/反序列化是否正确）。

【输入描述】

第一行一个整数 n；接下来 n 行，每行一个姓名和一个整数分数。

【输出描述】

输出 n 行，每行是从二进制文件里重新读出来的 "姓名 分数"，顺序与输入一致。

样例输入

2
Alice 90
Bob 88

样例输出

Alice 90
Bob 88

配套测试程序：mock9_prob2_binary_student_io.cpp（只检查最终标准输出内容，不检查 students.bin 文件本身的格式）
